# Data governance

A lightweight governance record for this project: who owns each dataset, how it is classified, where it comes from, and which quality rules protect it. It follows the usual pillars of a data governance framework (ownership, classification, catalogue, quality, lineage) at the scale of a single portfolio pipeline.

## Ownership

| Role | Who | Responsibility here |
|---|---|---|
| Data owner (source) | IMDA, publisher of the Annual Survey on Infocomm Usage | Defines the survey, its methodology and the published figures |
| Data custodian (distribution) | SingStat / data.gov.sg | Hosts and versions the open datasets |
| Data steward (this project) | Project maintainer | Maps source labels to segments, maintains the quality rules, approves changes to models |
| Data consumers | Readers of the README and dashboard | Use the marts and star schema for analysis; raise issues via GitHub |

## Classification

| Asset | Classification | Why |
|---|---|---|
| `data/raw/*.csv` | Public (open data) | Published under the Singapore Open Data Licence |
| `data/processed/*.csv` | Public (derived) | Aggregated percentages only; no individual-level or personal data |
| `data/digital_adoption.duckdb` | Internal (build artefact) | Regenerated by the pipeline; not committed |

No personal data is processed, so PDPA obligations don't apply. If individual-level survey data were ever added, it would be classified as Confidential and kept out of the repository.

## Data catalogue

| Dataset | Description | Source | Grain | Refresh | Quality rules |
|---|---|---|---|---|---|
| `stg_indicators` | Tidy staging table for all four indicators | data.gov.sg (4 datasets) | indicator × segment × year | Yearly, when IMDA publishes | 1–9 (pre-load) |
| `fact_adoption` | Star-schema fact table of adoption rates | `stg_indicators` | indicator × segment × year | With staging | Key, grain and reconciliation tests |
| `dim_indicator` / `dim_segment` / `dim_year` | Conformed dimensions | `stg_indicators` | one row per member | With staging | Unique, non-null keys |
| `mart_age_gap` | 18–39 vs 60+ gap and parity | `stg_indicators` | indicator × year | With staging | Gap arithmetic, parity range |
| `mart_adoption_ladder` | Drop-offs between ladder steps | `stg_indicators` | segment × year × step | With staging | Reconciles to staging |
| `mart_gap_change` | Gap closed, first → latest year | `mart_age_gap` | indicator | With staging | One row per indicator |

Field-level definitions live in [`data_dictionary.md`](data_dictionary.md).

## Quality rules

The nine pre-load rules in `src/checks.py` (listed in the README) act as the quality standard: error-level rules stop the pipeline, warning-level rules are flagged for a steward to review. Each rule has a test proving it catches an injected issue.

## Lineage

```
data.gov.sg API → data/raw (wide CSV) → raw_long (pandas) → stg_indicators
      → dim_* + fact_adoption (star schema)
      → mart_age_gap → mart_gap_change
      → mart_adoption_ladder
      → data/processed CSVs → charts and dashboard
```

## Change control

- A new survey year: run `scripts/download_data.py`, then the pipeline; rule 3 (year coverage) and `dim_year` flags update automatically once `YEARS` in `src/config.py` is extended.
- A new or renamed source label: rule 1 fails until `SEGMENT_MAP` is updated, so label drift can't pass silently.
